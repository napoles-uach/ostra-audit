# Contributing to OSTRA

OSTRA collects silent scientific errors in electronic-structure libraries, found with physics-based oracles and
verified before anything is reported. Contributions are welcome from people and from people working with AI agents:
new findings, independent verification of existing ones, new oracles or probes, and help with reports.

Read first: [`PROTOCOL.md`](PROTOCOL.md) (how a signal becomes a finding) and [`REPORTING.md`](REPORTING.md)
(how a finding becomes an upstream issue).

## Ground rules

1. **Never report upstream on your own.** No issues, comments or pull requests in the audited projects without
   agreement here; see `REPORTING.md`. Maintainers' time is the scarcest resource in this project.
2. **Nothing is a finding until it passes the protocol.** Unverified signals go to `candidates/`.
3. **Record the state at detection time** (versions, commits, inputs, raw outputs). Corrections are appended, never
   overwritten. Refuted and reclassified signals are kept in `discarded/`: they measure the method.
4. **Be fair to the code and its authors.** We describe fragile numerical decisions, not careless people.
5. **Declare AI assistance**: which model or tool did what, and what a human checked.
6. The repository is **private** for now. Do not share its contents outside the collaborators without agreement.

## Workflow (fork / branch / pull request)

```bash
# once
git clone https://github.com/<you>/ostra-audit.git      # your fork (or the main repo if you have write access)
cd ostra-audit
git remote add upstream https://github.com/napoles-uach/ostra-audit.git

# for each piece of work
git fetch upstream && git switch -c <you>/<topic> upstream/main
# ... work ...
python3 tools/make_index.py
git add -A && git commit -m "OSTRA-NNN: <short description>"
git push -u origin <you>/<topic>
# open a pull request against napoles-uach/ostra-audit:main
```

- One branch per topic (one finding, one verification, one batch of candidates). Never commit to `main` directly.
- Branch names: `<you>/<topic>`, e.g. `maria/libxc-pbe-threshold`, `gemini/verify-OSTRA-008`.
- Commit messages start with the finding ID when there is one.
- If an AI agent works for you, let it work in its own branch and folder, and review its commits before the PR.

## Adding a finding

1. **Claim the next ID** in the PR title or in an issue of this repository, to avoid collisions
   (`ls findings` shows the last one).
2. Copy the template:
   ```bash
   cp -r templates/OSTRA-NNN-library-short-name findings/OSTRA-027-libxc-short-name
   ```
3. Fill `finding.md` (the table fields are parsed by `tools/make_index.py`; keep the field names) and
   `environment.txt`. Put minimal reproducers in `repro/`, raw outputs in `evidence/`.
4. Status starts at `candidate` and advances only with evidence:
   `candidate → verified → attributed → impact measured → reported → resolved` (or `reclassified` / `refuted`).
5. Run `python3 tools/make_index.py` and commit the regenerated `findings/INDEX.md` and `findings/index.json`.
   Never edit those two files by hand.

## Verifying someone else's finding

Independent verification is the most valuable contribution and the condition for any upstream report.

- Work **blind** first: start from the claim and the source location only, write your own test, and do not reuse the
  original harness or numbers. Look at the original evidence and proposed patch only in a second phase.
- Put your scripts and outputs in `findings/OSTRA-NNN-*/verification/<you>-<date>/` and a short `result.md`
  stating: confirmed / corrected / not reproduced, and the evidence level reached
  (anomaly reproduced / cause identified / defect confirmed).
- A "not reproduced" is a valid and useful result. Report it.

## Exploring with an AI agent

- Raw exploration lives in `agents/<agent-name>/` (snapshots, notes, inventories). Do not commit embedded git
  repositories or downloaded third-party sources; record their URL and commit instead.
- Every signal an agent proposes goes to `candidates/` until someone else verifies it.
- Log what was proposed and how verification changed it in `agents/LOG.md`. This is part of the paper's data.

## Repository map

| Path | Content |
|---|---|
| `findings/OSTRA-NNN-*/` | One folder per finding (template in `templates/`) |
| `findings/INDEX.md`, `index.json` | Generated by `tools/make_index.py` |
| `candidates/` | Signals not yet verified |
| `discarded/` | Signals removed by the protocol, with the reason |
| `catalog/` | Fragile numerical decisions: recurring patterns with linked cases |
| `probes/` | General harnesses and scan results |
| `agents/` | Agent folders and `LOG.md` |
| `tools/` | Repository utilities |

## Authorship

People who contribute findings, verifications or substantial analysis will be invited to the paper. Discuss
authorship with the coordinator (J. M. Nápoles-Duarte) early; the PR history and `agents/LOG.md` document who did what.
